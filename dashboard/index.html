✅ Scanner Rules Reference

All checks performed by scan_policy_document() on each Allow statement

AIG001 High
Detects use of NotAction or NotResource in agent policies — difficult to reason about for autonomous workloads.
Trigger: Statement contains NotAction or NotResource key
AIG002 Critical
Flags wildcard service actions (* or service:*) that give agents unrestricted API access.
Trigger: Action ends with :* or is *
AIG003 High
Flags Resource: "*" — agent has access to all resources in the account.
Trigger: Resource list contains "*"
AIG004 Critical
Detects iam:PassRole without iam:PassedToService condition — agent can pass roles to any service.
Trigger: iam:PassRole action without condition constraint
AIG005 Critical
Flags privilege-management actions that let agents modify IAM or assume other roles.
Actions: iam:*, iam:CreateRole, iam:PutRolePolicy, iam:AttachRolePolicy, iam:CreatePolicy, iam:CreatePolicyVersion, iam:SetDefaultPolicyVersion, iam:PassRole, sts:AssumeRole
AIG006 High
Tool-execution actions without resource scoping — agent can invoke any function/command/task.
Actions: lambda:InvokeFunction, ssm:SendCommand, ssm:StartSession, states:StartExecution, ecs:RunTask, bedrock:Invoke*, bedrock-agent*:Invoke*
AIG007 Medium
Sensitive data access without principal/session tag conditions — no tenant isolation for agent data reads.
Actions: secretsmanager:GetSecretValue, ssm:GetParameter*, kms:Decrypt, s3:GetObject, logs:GetLogEvents

🚀 Run Instructions

Install

pip install aws-agent-identity-guard

Scan a Policy File (CLI)

aws-agent-identity-guard scan examples/agent_policy_wildcard.json

Scan Programmatically (Python)

from aws_agent_identity_guard import scan_policy_document import json with open("policy.json") as f:     doc = json.load(f) findings = scan_policy_document(doc) for f in findings:     print(f"{f.severity.upper()} [{f.rule_id}] {f.message}")

Run Tests

pytest tests/ -v --cov --cov-fail-under=80
